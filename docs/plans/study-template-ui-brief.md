# 공부 카테고리 기록 — UI 연결 인계

이 작업은 공부 기록 백엔드와 합쳐 하나의 사용자 기능을 완성한다. 정확한 최종 DTO와 백엔드 검증 근거는 `functional-progress.md`의 공부 기록 흐름 구역을 따른다. 완료 상태·검증 결과는 그 구역에만 기록한다.

## 사용자 흐름

1. 공부 탭에서 카테고리 관리로 들어가 이름과 NUMBER/TIME/SHORT_TEXT/CHECK/MEMO 항목·단위·순서를 저장한다. 정의 저장은 일정을 만들지 않는다.
2. 공부 추가에서 기존 카테고리를 선택하고 항목을 미리 본 뒤 제목·날짜·반복을 지정한다. 관리 왕복 중 일정 초안을 유지한다. 기존 Task/series API의 commandId와 templateSelection을 사용한다.
3. 오늘의 공부 항목에서 기록 폼을 연다. record-template의 현재 정의를 사용하고 실제 입력값만 fields로 보낸다. 빈 값과0/false를 구별한다. CHECK에는 미입력으로 지우는 수단이 있어야 한다.
4. 저장·동기화 이후 상세에서 기록 당시의 이름·형식·단위·순서를 보여준다. 카테고리를 새 버전으로 변경해도 과거 상세·수정은 원 snapshot을 유지한다.
5. 보관한 카테고리는 새 일정 선택에서 제외하되 기존 일정 기록은 가능하다. 충돌·통신 실패는 기존 초안/command 보존 규칙을 유지한다.

## 연결 지점

- `DomainPage.tsx`의 현재 추가 버튼은 단순히 `/today`로 이동한다. 공부 추가는 공부 유형이 선택된 공통 일정 추가 흐름으로 연결한다. 운동·클라이밍을 이 작업에서 재설계하지 않는다.
- `QuickAdd.tsx`와 `TodayPage.tsx`의 생성 callback에 선택한 templateSelection을 전달하고 commandId를 사용자 제출 단위로 보존한다. 두 번 클릭·불확실 재시도에 새 command를 만들지 않는다.
- 생성된 TemplateApi의 관리 메서드를 재사용한다. 목록 페이지 처리·소유자 query key·보관 후 무효화를 연결한다.
- `RecordPage`, `StudyFields`, `ActivityRecordPage`, `CorrectionDrafts`를 백엔드의 입력/응답 DTO 분리에 맞춘다. 응답용 snapshot/legacy 자료를 입력으로 다시 보내지 않는다.
- 기존 템플릿 없는 공부와 운동·클라이밍 기록을 유지한다. legacy 공부 자료는 읽기 전용으로 표시하고 메모 수정 때 사라지지 않도록 한다.
- 기존 모바일44px·도메인 최대820px·한국어 문구·라이트/다크를 재사용한다. 별도 시안 탐색이나 비차단 미관 정리로 범위를 늘리지 않는다.

## 검증

관리 저장 후Task미생성 → 카테고리선택 일정생성 → 일부항목/0/false 저장 → 정의이름·단위·순서변경 → 과거상세/수정의원정의유지 → 보관후새선택제외/기존기록허용을 실제 브라우저로 확인한다. 관련 component 회귀·build만 실행하고 이미 통과한 서버 검사는 반복하지 않는다. 전체 사용자 흐름 통합 시 백엔드와 UI를 함께 리뷰한다.

남은 운동·클라이밍 사용자 정의 흐름, 프로그램·타이머·알림 등의 전체 요구는 별도 남은 기능으로 유지한다. 공부 흐름만 완료하고 전체 목표를 달성했다고 선언하지 않는다.
